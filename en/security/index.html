T-015

Security and trust

Draft, not yet reviewed by a lawyer; not in force until the service opens.

In place today

  • Your account is yours alone. Every route answers only to the account holder, and identity comes only from a session the server issued.
  • Code the model writes runs in an isolated sandbox. Nothing it leaves behind is trusted.
  • A change to a file you gave us reaches you as a proposal, to accept or reject.
  • Stored keys are encrypted. The audit log is chained, so it cannot be altered.
  • A question that would carry your files out to the internet waits until you agree.
  • The cost cap is hard: before every model call, the call is checked against what is left, and refused if it does not fit.

What the agent reads is not an order

Documents, web pages and search results can hide instructions. ARCY treats them as material to work on.

  • Everything the agent reads from outside is fenced as data, with marks only the system can write.
  • Hidden text in a web page or a PDF is set aside and reported, not read as part of the content.
  • Outside content cannot make the agent send or keep anything. A message or a memory that carries an email address, a long token, an address or a passage copied from outside material, rather than from you, is refused.
  • We tested this with 6 cases and a model that obeys what it reads. Nothing was sent, kept, accepted or deleted.
  • Not covered yet: text read from the pixels of a picture, and instructions put in other words.

What the agent reads is something to work on, never an order to follow.

Not done yet

  • No external penetration test yet; reviews so far are internal.
  • No compliance certifications yet.
  • Some findings of the internal review are still open. They are closed before the service opens.

To report a weakness, see report a vulnerability.
